37Error Handling[[C37]]

37.1 কেন্দ্রীয় ব্যবস্থা

প্রতিটি route handler-এর ভিতরের কোড handleRoute()-এ মোড়ানো। ফলে কোথাও try/catch লিখতে হয় না, আর ত্রুটির উত্তরের আকারও সব জায়গায় এক।

export class ApiError extends Error {
  constructor(message, status = 400) { super(message); this.status = status; }
}

export async function handleRoute(fn) {
  try { return await fn(); }
  catch (error) {
    if (error instanceof ApiError) return fail(error.message, { status: error.status });
    console.error(error);                                   // সার্ভারের লগে বিস্তারিত
    return fail("Internal server error", { status: 500 });  // ক্লায়েন্টকে শুধু এইটুকু
  }
}
এখানে একটি নিরাপত্তা সিদ্ধান্ত লুকানো আছে

অপ্রত্যাশিত ত্রুটির বিস্তারিত (stack trace, SQL, ফাইলের পথ) কখনো ব্রাউজারে পাঠানো হয় না। সেগুলো শুধু server log-এ যায়। নাহলে আক্রমণকারী ত্রুটির বার্তা থেকে ডাটাবেসের গঠন বুঝে ফেলতে পারত।

37.3 ৪০৪ বনাম ৪০৩ — একটি সূক্ষ্ম সিদ্ধান্ত

অন্যের cart item ধরতে চাইলে 403 না দিয়ে 404 দেওয়া হয়:

if (!item || item.cart.userId !== userId) throw new ApiError("Cart item not found", 404);

কারণ 403 বললে আক্রমণকারী বুঝে যেত “এই id-টি সত্যিই আছে, শুধু আমার নয়” — অর্থাৎ অস্তিত্ব ফাঁস হতো। 404 দিলে সে কিছুই জানতে পারে না।

39Deployment — GitHub → Vercel → Neon → Blob[[C39]]

39.1 ধাপে ধাপে

  1. ডেভেলপার GitHub-এ push করেন (github.com/fardaus12345/fair-harvest)।
  2. GitHub-এর webhook Vercel-কে জানায়।
  3. Vercel npm install চালায় → postinstall হিসেবে prisma generate।
  4. npm run build চালায়, যার ভিতরে তিনটি ধাপ: 
    "build": "prisma generate && prisma migrate deploy && next build"
    অর্থাৎ প্রতিটি deploy-এ ডাটাবেসের migration নিজে থেকেই প্রয়োগ হয়ে যায়।
  5. Build সফল হলে Vercel serverless function ও CDN-এ প্রকাশ করে।
  6. চলার সময় অ্যাপ Neon PostgreSQL (pooled সংযোগ) ও Vercel Blob ব্যবহার করে।

39.3 Deployment-এ যে তিনটি প্রকৃত সমস্যা হয়েছিল ও সমাধান

সমস্যামূল কারণসমাধান
Build ব্যর্থ — “Failed to build / because it took more than 60 seconds” হোমপেজ static generation-এর সময় নিজের HTTP API-তে কল করছিল, কিন্তু সেই সময় server তো এখনো চালুই হয়নি — request ঝুলে থাকত safeApi()-তে server-side + relative base হলে সরাসরি fallback, এবং প্রতিটি fetch-এ ৫ সেকেন্ডের AbortSignal.timeout

ছবি আপলোডে ENOENT … mkdir '/var/task/…/storage' Production-এ STORAGE_PROVIDER সেট করা ছিল না, তাই ডিফল্ট local চলছিল — কিন্তু serverless ফাইল সিস্টেম read-only Vercel-এ STORAGE_PROVIDER=object + Blob store যুক্ত করা
ভাইভায় এটি বলুন

এই তিনটি ঘটনা প্রমাণ করে প্রজেক্টটি সত্যিই deploy করা হয়েছে এবং বাস্তব সমস্যার মুখোমুখি হয়ে সমাধান করা হয়েছে। “আমি শুধু localhost-এ চালিয়েছি” বলার চেয়ে এটি অনেক শক্তিশালী উত্তর।

39.4 Docker (বিকল্প পথ)

প্রজেক্টে একটি সরল Dockerfile আছে (node:22-alpine → npm install → npm run build → npm start, পোর্ট ৩০০০)। এটি Vercel ছাড়া অন্য কোথাও চালানোর সুযোগ রাখে, তবে প্রধান deployment পথ Vercel।

40.1 .env নাকি .env.local?

একটি ফাঁদ যা এই প্রজেক্টে বাস্তবে সমস্যা করেছিল: Prisma CLI শুধু .env পড়ে, কিন্তু Next.js .env ও .env.local দুটোই পড়ে। তাই DATABASE_URL ও DIRECT_URL অবশ্যই .env-এ রাখতে হয়, নাহলে prisma migrate ডাটাবেস খুঁজে পায় না। README-তেও এটি লেখা আছে।

42ভবিষ্যৎ উন্নয়ন (Future Scope)[[C42]]

প্রতিটি প্রস্তাব উপরের কোনো একটি প্রকৃত সীমাবদ্ধতা থেকে এসেছে — কল্পনা থেকে নয়।

#উন্নয়নকোন সীমাবদ্ধতা দূর করেবাস্তবায়নের পথ
1প্রকৃত payment gatewaydemo payment bKash/SSLCommerz-এর sandbox; PaymentMethod enum-এ নতুন মান, webhook দিয়ে PaymentStatus হালনাগাদ। বর্তমান Payment মডেলই যথেষ্ট।
2প্রকৃত সরকারি APIdemo registry officialGovApiProvider.js-এ আসল URL ও key বসানো, তারপর VERIFICATION_PROVIDER=official। অন্য কোনো ফাইল বদলাতে হবে না — abstraction-টি ঠিক এই জন্যই তৈরি।
3Notificationকোনো জানানোর ব্যবস্থা নেই একটি Notification মডেল + ইমেইল (Resend) বা SMS। Trigger point ইতিমধ্যেই আছে: verification সিদ্ধান্ত, order status, নতুন review।
4Distributed rate limitingin-memory সীমা Upstash Redis; enforceRateLimit()-এর ভিতরের Map-কে Redis দিয়ে বদলানো — interface একই থাকে।
5Refresh token + HttpOnly cookieটোকেন localStorage-এ, বাতিল করা যায় না স্বল্পমেয়াদি access token + দীর্ঘমেয়াদি refresh token ডাটাবেসে; logout-এ refresh token মুছে ফেলা।
6Server-side search + paginationclient-side search, pagination নেই Admin product search-এর মতোই mode: "insensitive" + skip/take; PostgreSQL full-text search ব্যবহার করা যায়।
7Order state machineযেকোনো status থেকে যেকোনোটিতে অনুমোদিত পরিবর্তনের একটি map; অবৈধ হলে 422।
8সম্পূর্ণ audit coverage৬টি কাজ লেখা হয় recordAudit() ইতিমধ্যেই আছে — শুধু বাকি route-এ যোগ করা; সাথে filter ও pagination।
9প্রকৃত QR কোডশুধু স্ট্রিং একটি QR library দিয়ে /trace/<id>-এর ছবি তৈরি, যা পণ্যের প্যাকেটে ছাপা যাবে।
10প্রকৃত ছবি বিশ্লেষণscanner ভুয়া একটি image classification মডেল; বর্তমান API contract অপরিবর্তিত রেখে ভিতরটা বদলানো যায়।
11ডেলিভারি সংযোগডেলিভারি নেই Courier partner API + Order-এ tracking নম্বর; SHIPPED event-এর সাথে সংযুক্ত।
12সুপারিশ ব্যবস্থানেই Order ইতিহাস থেকে collaborative filtering — ডেটা ইতিমধ্যেই আছে।
13মোবাইল অ্যাপশুধু ওয়েব @fair-harvest/sdk ইতিমধ্যেই REST client হিসেবে প্রস্তুত — React Native অ্যাপ সরাসরি এটি ব্যবহার করতে পারবে।
14CI/CD ও test সম্প্রসারণহাতে টেস্ট চালাতে হয় GitHub Actions-এ lint + test + build; পরে route-level integration ও Playwright E2E।
